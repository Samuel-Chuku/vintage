How it works · Try it

Try it in a sandbox.

Start a sandbox, copy a command from the list, paste it into the terminal. The vintage command checks real Zcash transactions against the public chain, and gets the same answers as the API. Nothing to install, nothing downloaded to your machine.

Commands to paste
i

These run in a sandbox: a disposable Linux machine on Beam, started for you, with the vintage command, the signed event registry and our demo files (demo/) pre-installed. It can reach only the Zcash data server (zec.rocks) and our API. It closes after 15 minutes and keeps nothing: no logs, no history. Your own machine runs nothing and downloads nothing.

  1. A stranger's coins, checked against the Bitget hack 
    vintage verify d3252057850259c86ffae437d0df207ff8b500e4d83dfe4409f585dcd6b441e4 --before bitget-2026-09
    Expect PASS: its coins were already in the pool.
  2. When were those coins in the pool? 
    vintage age d3252057850259c86ffae437d0df207ff8b500e4d83dfe4409f585dcd6b441e4
    Expect DATED: by block 3,499,995, on 29 September.
  3. Coins that arrived after an event 
    vintage verify a4c7622f2e3e39ce0cd5a65fc4417f490568990a6f90fda5579a924a0d83c143 --before vintage-demo-2026-10
    Expect FAIL: no proof of age. A fail flags nothing.
  4. Our Vintage payment, against our staged event 
    vintage verify da9017e0fca0d8bd87def8e3faa7956067f2bd2234cfee91ca7ad4e67095e3a7 --before vintage-demo-2026-10
    Expect PASS. Try --before bitget-2026-09 too: FAIL, the hack came first.
  5. Coins received after the event, linked with a viewing key 
    vintage link verify demo/mainnet-link-bundle.json --before vintage-demo-2026-10
    Expect PASS: both inputs came from the Vintage payment.
  6. The same link, no key (experimental) 
    vintage link verify demo/mainnet-zk-link.json --before vintage-demo-2026-10
    Expect ZK LINK PASS: two zero-knowledge proofs, no viewing key.
  7. The same, from our testnet run 
    vintage --network test link verify demo/testnet-zk-link.json --before 4562500
    Expect ZK LINK PASS.
  8. Any block height instead of an event, as JSON 
    vintage verify d3252057850259c86ffae437d0df207ff8b500e4d83dfe4409f585dcd6b441e4 --before 3501240 --json
    The API's report, from the command line.
  9. Real transactions to try your own checks on 
    vintage sample --blocks 3
    Most will FAIL: wallets anchor a few blocks back.
Want to test the API too?▾

Paste these into the same terminal; they call our public API. The last two send the demo files that are already in the sandbox.

  1. GET /verify: a transaction against an event 
    curl -s 'https://api.usevintage.site/verify/d3252057850259c86ffae437d0df207ff8b500e4d83dfe4409f585dcd6b441e4?before=bitget-2026-09'
    Expect "verdict":"PASS".
  2. GET /age: when were the coins in the pool? 
    curl -s https://api.usevintage.site/age/d3252057850259c86ffae437d0df207ff8b500e4d83dfe4409f585dcd6b441e4
    Expect "verdict":"DATED".
  3. GET /events: the signed registry 
    curl -s https://api.usevintage.site/events
    The two events and the registry's public key.
  4. GET /stats: the only thing we count 
    curl -s https://api.usevintage.site/stats
    Daily totals by verdict. No txids, no IPs.
  5. POST /verify-link: the viewing-key link 
    curl -s https://api.usevintage.site/verify-link -H 'content-type: application/json' -d "{\"before\":\"vintage-demo-2026-10\",\"bundle\":$(cat demo/mainnet-link-bundle.json)}"
    Expect "verdict":"PASS".
  6. POST /verify-zk-link: the link with zero-knowledge proofs 
    curl -s https://api.usevintage.site/verify-zk-link -H 'content-type: application/json' -d "{\"before\":\"vintage-demo-2026-10\",\"file\":$(cat demo/mainnet-zk-link.json)}"
    Expect "verdict":"PASS", 2 of 2 inputs proven.
